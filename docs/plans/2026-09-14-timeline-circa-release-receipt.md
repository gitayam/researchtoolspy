# Approximate recorded dates and behaviour time domains

The [timeline Analyst view](https://researchtools.net/dashboard/tools/timeline) can now record that a date is approximate. **Recorded date is approximate (circa)** sits under the recorded date in Add/Edit event and stays disabled until a date exists, because the qualifier has nothing to qualify without one. Display runs through the single temporal-label helper, so `circa 1979` reaches the analyst list, overlap and timing review, presentation schedule, narrative, assist and the TimelineJS display date from one place.

Circa qualifies the recorded value and nothing more. It never moves an event, never changes precision and never invents a window, so a recorded-date review of an approximate timeline is identical to the exact one. That equivalence is asserted directly rather than described.

This is workspace `v3`, not an addition to `v2`. The decoder validates an exact key allow-list per version, so a new key inside `v2` would make every existing `v2` consumer reject the payload. Version still follows content: a timeline using neither circa nor intervals exports `v1` byte-for-byte, and the browser draft version mirrors it. **TL-06 remains in progress**; clock mappings for the evidence timeline and extraction v2 remain pending.

Behaviour analysis gained the time-domain half of the same work. Its timeline is a reusable pattern, not a dated record, but `time` was free text documented as `HH:MM or relative like T+30min`, so a clock reading and an elapsed offset were the same untyped string and nothing could order, compare or validate them. The two halves of the product disagreed in public: the AI generator emits `T+0min` while the editor's own placeholder invited `Day 1` and `9:00 AM`. A behaviour timeline now declares one domain — `anchor_relative` with parsed `T±` offsets, or `ordinal` for sequence without elapsed time, where the offset field is disabled rather than inviting a value the domain cannot hold. `absolute` is deliberately absent. Timing review reports offsets that cannot be read and offsets that contradict step order, and is read-only.

Clock mapping is the bridge to a dated presentation. Anchoring `T+0` to an analyst-supplied instant resolves each offset to a real instant, so one template can be placed against different incidents without being edited; the mapping is a projection, not a mutation. Steps without a readable offset are reported as omitted rather than given a guessed time. TimelineJS was **not** wired directly to behaviour timelines: `buildTimelineJSExport` omits any event lacking an absolute date, so with no dates it would omit every event. The anchor has to come first. The declared domain is persisted beside the events under the existing `${section.key}_*` convention that PMESII-PT already uses for linked actors; an unrecognised stored value falls back rather than being trusted.

Accepted source `94677ad63` is on both main refs and deployed as `6c047aea` at [the accepted build](https://6c047aea.researchtoolspy.pages.dev). Production returns HTTP 200 and the deployed assets carry the new strings: `circa` and `Recorded date is approximate` in the timeline chunk, and `Place on a clock`, `anchor_relative`, `Offset from start`, `Sequence only` and `Timing review` in the framework chunk. Zero managed migrations were pending, so no production data was touched.

## Verification, and what it does not cover

Checks run: 6 circa contracts, 5 behaviour time-domain contracts, 9 interval contracts, 10 timeline tool UI cases, 8 existing behaviour specs, plus the TimelineJS and timing browser specs — 30 in the combined timeline run and 13 in the combined behaviour run, all on chromium. Five type checks via `tsc -b`, and the frontend build. Lint on every touched file is unchanged from main: the two findings in the recorded-date component and results view, and 107 in the generic framework form and view, are all present on main at the same rules.

This is a weaker gate than prior tranches in this series and should not be read as equivalent. Checks ran under host Playwright, not the pinned credential-free network-none container the earlier charters require. The mobile-safari project was not run; no light/dark desktop/mobile captures were taken; no independent source review, package-file review or edge-replay exemption applies here. The compiled production-schema gate was exercised only as part of `deploy.sh`.

Two pre-existing failures were repaired rather than worked around. `timeline-tool-ui` cases at lines 156 and 317 were already failing on main: `getByLabel('Date')` had been ambiguous since the overlap and date-entry tranches added **Compare recorded dates for** and **Select date precision**, and exact matching then fails because the label reads `Date (optional)` under non-absolute placement. Both now target the input's own id. The interval contract's unknown-version probe asserted that `timeline-workspace.v3` must be rejected; its subject is an unknown future version and v3 was simply the next one that did not exist, so the probe moved to v4 and the new spec covers v3 explicitly. Neither change weakens an oracle.

The behaviour domain is persisted but has no browser round-trip test; it is covered by type checking and the contract suite for the library beneath it. Visual review is representative, not accessibility certification or user testing. The full unrelated API suite is not claimed.
